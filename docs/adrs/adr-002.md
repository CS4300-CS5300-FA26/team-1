# Use Postgres for prod DB engine
Date: 2026-10-01

## Status
Accepted

## Decision
We will use Postgres for the production database engine.

## What Postgres offers
* First-class Django support: Postgres is widely supported, with a dedicated django.contrib.postgres package (JSONB, array, and range fields, full-text search) and the most community documentation and third-party package support.
* Transactional DDL: a failed migration rolls back cleanly instead of leaving the schema half-applied.
* Managed hosting on our platform: Cloud SQL offers PostgreSQL, MySQL, and SQL Server, but not MariaDB, so Postgres gives us automated backups and patching without self-managing a database in the cluster.
* Room to grow: JSONB and full-text search are useful for workout plan data and an exercise library if the schema becomes more complex.
* Learning goal: the team wants experience with Postgres.

## Tradeoffs considered
* Learning curve: Postgres behaves differently from MariaDB/MySQL in places, such as case-sensitive string comparisons and the psycopg driver instead of mysqlclient.
* Dev/prod parity: SQLite or another engine locally would hide Postgres-specific behavior, so we run Postgres in Docker Compose and in CI instead.
* Cost and availability: Cloud SQL runs continuously and is billed against the trial credit. We use the smallest tier without HA, so the database is a single point of failure. Mitigations are automated backups and deletion protection.
* Postgres-specific features: using django.contrib.postgres fields ties code to Postgres. We use them only where they clearly help.
* Alternatives rejected: MariaDB is familiar to the team but is not offered by Cloud SQL (we would self-manage it in the cluster) and lacks transactional DDL. MySQL on Cloud SQL is supported but has fewer Django features and commits DDL implicitly. SQLite is not suitable for a multi-user production deployment.
* Reversibility: the Django ORM abstracts most differences, so switching engines is feasible if we avoid raw SQL and Postgres-only fields. Data would be moved with dumpdata/loaddata or a migration tool.
