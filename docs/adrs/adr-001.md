# Use uv for Python package and environment management
Date: 2026-09-29

## Status
Accepted

## Decision
We will use uv to manage Python versions, virtual environments, and dependencies for FitPro.

## What uv offers
* Lockfile: uv.lock pins every direct and transitive dependency, so all developers, CI, and the production container install identical versions.
* Python version management: .python-version and requires-python pin the interpreter, and uv can download it if it is missing.
* One tool for the workflow: uv add, uv sync, and uv run handle the virtual environment, installs, and command execution, with no manual venv activation.
* Speed: installs are fast, which helps CI and Docker image builds.
* Docker and CI support: installs can be made to fail if the lockfile is out of date (uv sync --locked).

## Tradeoffs considered
* Learning curve: The team must learn uv add / uv sync / uv run instead of pip install. Using plain pip in the environment bypasses the lockfile and should be avoided.
* Extra tool: uv must be installed on each developer machine, in CI, and in the Dockerfile. The baseline (python -m venv + pip) needs no extra tooling but has no lockfile and does not manage the Python version.
* Lockfile merge conflicts: Concurrent dependency changes can conflict in uv.lock. Resolve by re-running uv lock, not by hand-editing.
* Reversibility: If uv becomes a blocker, uv export can produce a requirements.txt to fall back to pip.
