# Store each user's weekly workout plan as JSON, one row per user per week
Date: 2026-11-03

## Status
Accepted

## Decision
Story D-3 (weekly workout plan and macro targets) lives in the `plans` app. The generator
(`plans/generator.py`) is pure Python: it turns a user's onboarding profile into a seven-day plan and daily
macro targets using fixed rules. The result is saved in `WeeklyPlan`, which has a `user`, a `week_start` (the
Monday), and the plan itself in a `JSONField`.

* **One plan per user per week.** A database unique constraint on (`user`, `week_start`) enforces it, and
  `get_or_create` means two simultaneous first visits can't create two plans. The user sees the same plan all week.
* **Generated on first visit.** The first time a user opens This Week or Nutrition in a new week, the plan is
  generated and saved; later visits reuse it.
* **The starter plan is never saved.** If the generator raises any error, the pages show a fixed 3-day bodyweight
  starter plan with a notice, and the failure is logged. Because nothing is saved, the next visit tries the
  generator again.
* **Reads are per user.** Pages read only the signed-in user's profile and plan.

## Tradeoffs considered
* **Generate on every visit (nothing stored):** simpler, but the plan could change between visits if the
  generator or profile changed, and it repeats work. Rejected.
* **Relational tables (workout, exercise, set rows):** would allow queries such as "who has squats this week", but
  every change to the exercise library would need a migration. Rejected for now; JSON lets the library change
  freely.
* **Saving the starter plan too:** would lock a user into the fallback for the week even after the generator
  recovers. Rejected.

## Consequences
* Saved plans can't easily be queried by their contents.
* A saved plan is not remade when the profile changes mid-week. A "regenerate" action would fix this.
* "Today" and the week boundary use the server's time zone (UTC), as in ADR-008.
* The macro estimate assumes age 25 and a sex-neutral formula, because onboarding doesn't collect them yet.
* The meal plan (ADR-008) reaches this feature through its D-3 and D-4 connectors; wiring them is a follow-up.
