# Track workouts of the plans app's weekly split, with how-to steps from a text-only exercise catalog
Date: 2026-11-17

## Status
Proposed

## Decision
Exercise tracking lives in a new `workouts` app that builds on the weekly plan from [ADR-012](adr-012.md). The
`plans` app stays the only place a split is generated and the only This Week page; `workouts` adds a way to do each
training day of that plan, log its sets, and see progress. An earlier version of this branch had its own planner,
plan tables, and This Week page at `/workouts/`; they were removed so there is one plan and one page.

| Part | Where | What it does |
| --- | --- | --- |
| Start / Continue on This Week | `plans/tracking.py` (connector), `workouts/tracker.py` (implementation), `PLANS_WORKOUT_TRACKER` | For each training day of the week's **saved** plan, This Week shows Start workout (a `POST` form), Continue workout, or View workout, plus a Workout history link. `plans` only knows the tracker by its dotted path, in the style of [ADR-008](adr-008.md)'s connectors, so it never imports `workouts`. With the setting unset or the tracker failing (logged), This Week shows the plan without buttons. The unsaved starter plan gets no buttons |
| Sessions | `WorkoutSession` | One per training day of a `plans.WeeklyPlan` (a database `UniqueConstraint` on plan and day, so a double click can't make two). It copies that day's exercises (`name`, `sets`, `reps`, the plan's own shape) when it starts, so switching the split later ([ADR-013](adr-013.md)) doesn't change a workout under way or done. Kept if the plan row goes |
| Sets | `LoggedSet` | Keyed by the exercise's position in the session and the set number. Exactly one of reps (with an optional weight), seconds (a hold, from reps text like `30-45 sec`), or minutes (cardio, `20 min`), enforced by a `CHECK` constraint. The exercise name is copied so the last weight can be offered next time |
| Reading the plan's targets | `workouts/domain.parse_target` | Turns the plan's `reps` text into what is logged. Unknown text is logged as reps, so a new format in the generator never blocks logging |
| Rest timer | `domain.Target.rest_seconds`, `rest_timer.js` | The generator doesn't prescribe rest, so: 90 s between sets of 12 reps or fewer, 60 s for lighter sets, 45 s for holds, none for cardio. Progressive enhancement: without JavaScript the rest time is text |
| How-to steps | `workouts/data/exercise_catalog.json`, `Exercise`, `exercise_links.py` | 1,324 exercises with English steps, **no images or video**. Each name the generator uses is linked by hand to the same movement in the catalog, or to nothing when the catalog has no close match (the exercise is still logged, just without steps). A test fails if the generator gains a name the list doesn't have |
| Catalog loading | `catalog_loader.py`, `apps.py`, `manage.py load_exercise_catalog`, `manage.py build_exercise_catalog` | The recipe catalog's pattern: validated, one transaction, idempotent, run after every `migrate`. An exercise that leaves the file is marked inactive |
| Pages | `/workouts/start/<day>/` (`POST`), `/workouts/session/<id>/`, `/workouts/history/` | Log a workout (how-to steps, a row per set, weights start from last time, save or finish); weekly consistency (done against the plan's training days) and volume, with recent workouts |

`NUTRITION_WORKOUTS_LINK`, the dashboard, and the header all point at the `plans` This Week page.

**Data privacy.** Every view is `login_required`. Starting only reads the signed-in user's own plan for the current
week (`start_session` also refuses a plan that isn't theirs), sessions are looked up by `user`, so another user's
workout is a 404, and history only reads the user's own rows. Logged-in tests prove it for start, view, save, and
history. State changes are `POST` with CSRF. Posted field names are built from the form's own rows, so values for rows
that aren't in the workout are ignored. Reps, weight, seconds, and minutes are bounded in the form and by the
database.

## What this offers
* **One plan.** D-3's split, its rotation and switches (ADR-013), and the macro targets the meal plan uses (ADR-012)
  all stay in `plans`; tracking can't disagree with them because it reads them.
* **A one-way dependency.** `workouts` imports `plans`; `plans` doesn't import `workouts`. Removing the app or the
  setting leaves This Week working.
* No new dependency, service, paid API, or datastore, and nothing that calls the network.
* The catalog keeps the repository small: the upstream file is 17.4 MB because every instruction is repeated in ten
  languages; the catalog is 0.97 MB.

## Tradeoffs considered
* **Linking sessions to the plan vs copying the day.** A session only pointing at the plan's JSON would change when
  the user switches split mid-week. Copying the day's few exercises costs a little storage and keeps finished
  workouts exactly as they were done.
* **A connector vs `plans` importing `workouts`.** A direct import is less code but makes the two apps depend on each
  other. The connector follows the pattern the meal plan already uses and lets either app be tested alone.
* **Keeping the earlier `workouts` planner.** It chose from about 130 catalog exercises and let users pick training
  days, but it was a second planner with its own This Week page. Those ideas can go into `plans/generator.py` later
  if the team wants them.
* **Media and licence.** The dataset's MIT grant covers the code, data structure, and instruction text. The images
  and videos are Gym visual's and are *not* licensed to us. `build_exercise_catalog` drops every media field, with a
  test that fails if one comes back. Using them would need FitPro's own licence, blob storage, and a new ADR.
* **English only.** Dropping nine languages loses nothing the app uses today.
* **Rest times are a rule of thumb.** They are ours, not a trainer's, and should be reviewed by someone qualified.
* **No rate limit on the new endpoints.** They don't authenticate, send email, or call anything external.

## Known limitations
* Logging only prefills the last weight used; progression (adding weight or reps) is a follow-up.
* 31 of the 45 exercise names have catalog steps linked; the other 14 (some banded and bodyweight moves, the plank, and cardio) show none.
* Only the current week's plan can be started. A week whose plan wasn't saved (the starter plan) can't be logged.
* "Today" and the week boundary use the server's time zone (UTC), as the meal plan does.
