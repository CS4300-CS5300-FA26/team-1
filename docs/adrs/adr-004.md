# Use a DNS-only Cloudflare subdomain with Google-managed TLS until we buy a domain
Date: 2026-10-01

## Status
Accepted

## Decision
We will serve FitPro over HTTPS from a subdomain of the Caleb's existing Cloudflare-managed domain (fitpro.rockymountaintechlab.com). The DNS record will be DNS only (gray cloud) and point at the load balancer's reserved static IP, with TLS handled by a Google-managed certificate through Certificate Manager. When the team purchases its own domain, we will move to that domain, with DNS hosted at the registrar we buy from, and retire the temporary subdomain.

## What this offers
* HTTPS from the first deploy: logins and session cookies are never sent in plain text, and browsers show no security warnings.
* No added cost: Certificate Manager is free for the first 100 certificates, and the subdomain is on a domain we already have.
* Fully managed certificates: Google issues and renews the certificate automatically, so there is nothing to rotate.
* Cloudflare stays out of the traffic path: with DNS only, browsers connect directly to the Google load balancer, so Cloudflare adds no extra point of failure or configuration.
* Easy migration: Certificate Manager can provision the new domain's certificate in advance with DNS authorization, so we can switch domains without downtime. The static IP, load balancer, cluster, and database do not change.

## Tradeoffs considered
* Personal domain: the app temporarily runs on the Caleb's domain, and only the owner can change its DNS. This is acceptable for a class project and is removed once the team domain is purchased. Django's session cookie domain is left unset so cookies stay scoped to the subdomain.
* Cloudflare proxy (orange cloud): would add DDoS protection and hide the origin IP, but Google-managed certificates fail to provision when DNS points at Cloudflare instead of the load balancer. It would require a Cloudflare Origin CA certificate managed by hand instead. Rejected as more setup for little benefit at our scale.
* Cloudflare Tunnel: removes the need for a load balancer, but adds a component to run for uptime and ties traffic to Cloudflare. Rejected for the same reason.
* HTTP on the raw static IP: no setup, but credentials and cookies would travel unencrypted. Rejected.
* Self-signed certificate on the raw IP: encrypts traffic but triggers browser warnings for every user, including the grader. Rejected.
* Migration effort: switching domains requires a new certificate, a DNS record, routing and Django host settings, and an optional redirect from the old hostname. Users will be logged out once, since sessions are tied to the hostname.
